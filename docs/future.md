# 今後の実装予定（ロードマップ）

「今すぐ必要ではないが、次に困りそうな点」「運用の安全性/可観測性を上げる点」を中心に、優先度付きで整理します。

## 優先度: 高（運用事故を減らす）

1) **CPU制限の設定**
- `config/bot.env` に `MC_CPU_LIMIT` を追加し、`mc-prod` 生成時に `NanoCpus` を設定する

2) **ステータスの精度改善**
- `/status` で「コンテナがrunning」だけでなく「Minecraftが起動完了して25565をlistenしているか」も表示
- 例: `docker exec` で `ss -ltn` を見る / logsの `Done (` を検知する

3) **安全な停止**
- `/stop` の順序を厳密化（RCON `save-all` → `stop` → docker remove）
- RCONが不通のときは警告して強制停止に切り替える

4) **設定ミス検出**
- `/start` 前に `server.env` の必須キー（`EULA`, `TYPE`, `VERSION`, `RCON_PASSWORD` など）をチェックし、typoを早期に弾く

## 優先度: 中（便利機能）

1) **サーバー作成補助**
- `data/<server-name>/` の雛形生成（最低限の `server.env` を作る）
- ※サーバーデータは手動運用前提のまま

2) **ログの取り回し**
- `/tail` のようなコマンドで `mc-prod` の直近ログをDiscordに返す（個人情報/長文に注意）

## 優先度: 低（将来案）

1) **チャット同期（Minecraft → Discord 片方向）**
- まずはログ監視等で通知

2) **バックアップ**
- `data/<server-name>/` のバックアップ作成、復元手順の整備

3) **認可（必要になったら）**
- 現状は「身内のみ」前提で無効
- 将来的にロールIDやユーザーIDで制限できるように戻す
